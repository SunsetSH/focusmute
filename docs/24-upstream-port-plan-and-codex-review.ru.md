# План финального переноса upstream 0.12.1 и разбор ревью codex

Дата: 2026-11-22. База: этот репозиторий `0705704` (FocusMute 1.1.0) и [barnumbirr/focusmute](https://github.com/barnumbirr/focusmute) `113384c` (Release 0.12.1). Продолжение [22](22-upstream-comparison-and-code-review.ru.md), раздел 8.6, и разбор [23](23-windows-code-review.ru.md).

## 1. Итог

| Вопрос | Ответ |
|---|---|
| Можно ли просто смержить upstream | Нет. У форка и upstream нет общих коммитов (`a209450` и `b28845f` из upstream здесь отсутствуют), `git merge` и `cherry-pick` не применятся. Перенос — вручную, по одному upstream-коммиту за этап. |
| Что переносить | `09daf68` (смещения в профиле, профиль Solo, смещения из схемы), `d824e86` (заголовок прошивки 3.x), `3293850` (данные halo Solo), обновление зависимостей из `6ec704b`. Подробно — раздел 2. |
| Главный риск | Если перенести только распознавание заголовка 3.x, Solo на прошивке 3.x станет корректно распознаваться, и сразу заработают жёстко заданные смещения Direct (`216/217/264`) и LED Lab (`72/88/62/264`). На 3.x это чужие поля дескриптора. Поэтому заголовок и перенос всех Solo-констант в профиль — один этап. |
| Как не сломать Solo | Сначала записать «эталонные» последовательности записей в устройство для всех режимов Solo на текущем коде. Затем рефакторинг должен дать байт-в-байт ту же последовательность. Раздел 5, этап 0. |
| Ревью codex | Из 6 крупных пунктов полностью подтверждён один (запуск без микрофона), остальные подтверждены частично. Часть решений избыточна для приложения на одну карту. Короткие исправления — раздел 7.3. |

## 3. Как Solo работает сейчас

Это нужно зафиксировать, чтобы после переноса поведение не поменялось.

**Цепочка.** `detect_model("Scarlett Solo 4th Gen")` возвращает `None` → `DeviceContext::resolve` читает схему (из `%APPDATA%\Focusmute\schema_cache.json`, сейчас fw `2.0.2417.0`) → `predict_layout` → `MuteStrategy` с предсказанными номерами LED. Дальше [ops.rs](../crates/focusmute-lib/src/led/ops.rs) по имени модели (`is_solo`) **игнорирует** предсказание и пишет в LED 4 / 12.

**Solo-константы в коде** (все откалиброваны на прошивке 2.0.2417.0):

| Где | Что | Значения |
|---|---|---|
| [ops.rs:10](../crates/focusmute-lib/src/led/ops.rs#L10) | single-LED запись | colour 80, index 84, notify 8 |
| [ops.rs:59](../crates/focusmute-lib/src/led/ops.rs#L59) | restore номеров | белый `0xAAFF_DD00`, без `selectedInput` |
| [ops.rs:173](../crates/focusmute-lib/src/led/ops.rs#L173) | режим `extended` | Solo: LED 4, 12, 24, 25, restore белым. 2i2: 0, 8, 37, 38, restore `0x7080_8800` |
| [solo.rs](../crates/focusmute-lib/src/led/solo.rs) | номера, белый, LED Lab | 4, 12, `WHITE` |
| [direct.rs](../crates/focusmute-lib/src/direct.rs) | Direct Monitor | состояние 264, parameter buffer 216/217, notify 12, маски `0x0080_0000` и `0x0400_0000` |
| [settings_dialog/ui.rs:538](../crates/focusmute/src/settings_dialog/ui.rs#L538) | диагностика LED Lab | 72, 264, 88 (128 байт), 62 |
| [settings_dialog/mod.rs:102](../crates/focusmute/src/settings_dialog/mod.rs#L102), [shared.rs:560](../crates/focusmute/src/tray/shared.rs#L560), [state/mod.rs:501](../crates/focusmute/src/tray/state/mod.rs#L501) | проверки модели по строке | `is_solo` |

`DeviceContext.offsets` в трее не используется вообще: только в `focusmute-cli map`.

**Скрытые дефекты, найденные при анализе (есть уже сейчас):**

1. **`map` на Solo пишет режим LED в 77.** `DeviceOffsets::from_schema` берёт `enable_direct_led` из константы 2i2 ([offsets.rs:35](../crates/focusmute-lib/src/offsets.rs#L35)), а у Solo по адресу 77 лежит `directMonitorAltOffset` (док. 18). Перенос `09daf68` это исправляет: смещение берётся из схемы (72).
2. **Solo на прошивке 3.x.** Имя читается со смещения 16, а на 3.x оно на 40. `model()` вернёт мусор, `is_solo` = false, и выполнение уйдёт в общую ветку: запись цвета в 84/88 (константы 2i2) и чтение `selectedInput` из 331 — на сдвинутом на 24 байта дескрипторе Solo. **До выхода версии с этим этапом прошивку Solo через Focusrite Control 2 до 3.x не обновлять.**
3. **Ошибка контекста после открытия.** `try_reopen` фиксирует успех до `reinit_device_context` ([reconnect.rs:101](../crates/focusmute-lib/src/reconnect.rs#L101)). Если контекст не разрешился, следующая попытка — уже через 50 мс, и для модели без профиля это каждый раз чтение схемы.

## 4. Риски и решения

| # | Риск | Чем грозит Solo | Решение |
|---|---|---|---|
| R1 | Перенос `HeaderLayout` без переноса Solo-констант | На 3.x Solo распознаётся, Direct пишет 216/217 в чужие поля, LED Lab читает не то | Делать в одном этапе с R2. Все Solo-смещения — в профиль. На не-V2 профиль даёт только индексы LED, смещения — только из схемы. Функции без смещений из схемы (Direct, LED Lab) на не-V2 выключены |
| R2 | Проверки `is_solo` по имени остаются рядом с профилем | Две логики выбора модели расходятся: например, профиль есть, а `is_solo` false из-за регистра или суффикса | Убрать `is_solo` полностью. Возможности модели описывает профиль: `ModelProfile.direct: Option<&DirectControl>`, `ModelProfile.output_indicator`. Код спрашивает «есть ли у модели Direct», а не «это Solo» |
| R3 | Рефакторинг меняет порядок или состав записей | Другой цвет restore, лишний LED, перепутанный порядок colour → index | Характеризационные тесты до рефакторинга (этап 0). Проверяется последовательность `SET_DESCR`/`DATA_NOTIFY`, а не только итоговое состояние |
| R4 | Профиль Solo отключает чтение схемы, а кто-то читал `ctx.schema` / `ctx.predicted` | Пропадут данные в `status` / «О программе» | Проверено: трей использует только `input_count()` и стратегию, а их даёт профиль. `status` и `probe` показывают схему, если она есть, — для Solo там станет «schema: skipped (profile)». Добавить тест `solo_profile_skips_schema_and_keeps_input_count` |
| R5 | `ProfileSource::Reported` из upstream | На каждом старте предупреждение «layout unverified» про собственную карту автора | В форке `ProfileSource::Verified`: номера 4/12, Output 24/25, смещения 72/80/84/88 проверены на этом устройстве. В комментарии оставить, что LED 13 не наблюдался и белый цвет подобран по 2i2 |
| R6 | Режим `extended` отсутствует в upstream | При переносе ops.rs «по образцу upstream» режим потеряется | Расширить `ModelProfile` полем `output_indicator: Option<OutputIndicator { leds: &[u8], restore: u32 }>`. 2i2: `[37, 38]`, `0x7080_8800`. Solo: `[24, 25]`, `0xAAFF_DD00`. `extended` = номера из `input_halos` + `output_indicator.leds` |
| R7 | `MuteStrategy` получает поле `offsets` | Пустая стратегия без устройства (`init_without_device`) пишет по смещениям по умолчанию | Пустая стратегия по-прежнему без LED (`number_leds = []`), записей нет. Тест на это уже есть, его нужно сохранить |
| R8 | Кэш схемы формата 2 | — | Для Solo кэш больше не читается. Для неизвестных моделей — однократное перечитывание. Безопасно |
| R9 | Нет схемы Solo 3.x | Путь V3 для Solo нельзя проверить на реальных данных | Синтетический тест: схема Solo со всеми смещениями +24 и V3-заголовок с именем на 40. Ожидание: записи только по смещениям из схемы и ни одной записи по 80/84/216/217. V3 без схемы → `UnsupportedDevice` и ноль записей. Когда появится Solo на 3.x — снять схему (`focusmute-cli probe`) и добавить fixture |
| R10 | `rodio` 0.23, `tray-icon` 0.26, `muda` 0.21 меняют API | Звук, меню, иконка | Отдельный этап и коммит. Проверка звука на слух, меню на Windows |
| R11 | Ручной перенос пропустит фрагмент | Половинчатое состояние | Чек-лист файлов из `git show --stat` каждого upstream-коммита. После этапа сравнить `diff` своих файлов с upstream `113384c` — расхождения допустимы только в местах из R5–R7 |

## 5. План по этапам

Всё — в ветке `upstream-0.12-port`, один этап = один коммит (или серия коммитов), каждый проходит `fmt`, `clippy -D warnings` (обе цели) и `test`.

### Этап 0. Подготовка и эталон (без изменения поведения)

1. В `MockDevice` добавить упорядоченный журнал: `ops: RefCell<Vec<MockOp>>`, где `MockOp::{Get(off, len), Set(off, bytes), Notify(id)}`. Сейчас `descriptors` — `HashMap`, и порядок записей потерян.
2. Тесты `tests/solo_golden.rs` на текущем коде. Для Solo (fw 2.x) и 2i2 зафиксировать журнал для сценариев:
   - `mute_inputs` = `all`, `1`, `2`, `1,2`; per-input цвета;
   - режимы `numbers`, `numbers_blink` (кадр blank и кадр цвета), `extended`, `halos_solid` (fallback);
   - apply → clear, `restore_on_exit`, `refresh_after_reconnect`;
   - Direct: `set_solo_direct_enabled(true/false)`, разбор масок;
   - LED Lab: `test_led` и `restore_test`.
3. Ручной baseline на устройстве: прогнать чек-лист из раздела 6 на 1.1.0 и записать результат.

**Критерий:** журналы сохранены как константы в тесте и проходят на `0705704`.

### Этап 1. Смещения из схемы (по `09daf68`, часть 1)

- `SchemaConstants`: `enable_direct_led_offset`, `direct_led_notify`, `direct_led_colour_offset`, `direct_led_index_offset`, `direct_led_colour_notify`, `selected_input_offset: Option`. Плюс поля форка: `direct_monitoring_offset`, `parameter_value_offset`, `parameter_channel_offset`, notify-device для `directMonitoring` и `input_air_offset` — все `Option`. `SCHEMA_FORMAT_VERSION` +1.
- `DeviceOffsets`: те же поля, `nonzero_or`, `Default` = 2i2.
- Тест: схема Solo 2.0.2417.0 (снять с устройства через `probe`, положить в `docs/device_firmware_schema_solo_2.0.2417.0.json`) даёт 72/80/84/88/8/`None`/216/217/264/62.

Поведение не меняется: `ops.rs` ещё не трогаем. Golden-тесты зелёные.

### Этап 2. Профиль Solo и удаление `is_solo` (по `09daf68`, часть 2, и `3293850`)

- `ModelProfile`: `offsets`, `source`, плюс поля форка `output_indicator` и `direct: Option<&'static DirectControl>`. `DirectControl { state_offset: 264, param_value: 216, param_channel: 217, notify: 12, direct_mask, video_call_mask }`.
- `SCARLETT_SOLO` с halo `5..12` / `13..20`, `output_halo_segments: 20..20`, `button_labels: &[]`, `cache_dependent_buttons: &[]`, `Verified`. `SCARLETT_2I2` дополняется `output_indicator`, `direct: None`.
- `MuteStrategy.offsets`, `set_single_led(device, offsets, index, color)`, `restore_number_leds` по `selected_input: Option` — как в upstream.
- В `ops.rs` нет ни одной проверки имени модели. `extended` строится из профиля (R6). `solo.rs` остаётся только для LED Lab и берёт смещения и индексы из контекста.
- `direct.rs`: функции принимают `&DirectControl`. В трее `direct_wanted = option && ctx.direct().is_some()`.
- `context.rs`: `resolve_at`, профиль отдаёт свои смещения, predict при наличии схемы.
- Тест инвариантов раскладки для всех профилей.

**Критерий:** golden-журналы Solo и 2i2 совпадают байт в байт. Единственное ожидаемое изменение — `map` на Solo пишет режим в 72, а не в 77 (дефект 1). Это отдельный тест.

### Этап 3. Заголовок прошивки 3.x (по `d824e86`)

- `HeaderLayout`, `HEADER_LEN = 72`, `apply_header`, `is_product_name`; в Windows и Linux `open()` — один `get_descriptor(0, 72)`.
- `DeviceContext`: на не-V2 схема читается всегда. Профиль даёт индексы LED и цвета, но не смещения. Без схемы — `UnsupportedDevice`.
- `ctx.direct()` и LED Lab: на не-V2 возвращают `None`, пока не получена проверенная схема Solo 3.x (R1, R9).
- Удалить мёртвые константы 2i2 (`OFF_PARAMETER_VALUE` и др.), как в upstream.
- В журнал старта и в «О программе»: `firmware 2.0.2417.0 (layout V2)`.
- Тесты из upstream (`apply_header_*`, `firmware_3_profiled_device_takes_offsets_from_the_schema`, `non_v2_layout_never_falls_back_to_profile_offsets`) и синтетический Solo V3 из R9.

### Этап 4. Мелочи upstream

- `predict_layout`: halo → `Medium`. `generate_model_profile_code` выдаёт компилирующийся код с `offsets`.
- `map` и `probe` используют `ctx.offsets` (после этапа 2 для Solo это уже верные значения).
- udev-файл: убрать BOM и `` `n ``.

### Этап 5. Зависимости

- `tray-icon` 0.26, `muda` 0.21, `dirs` 7, `notify-rust`, `clap`. `windows-core` держать на 0.62 и закрепить в `dependabot.yml`.
- `rodio` 0.23. Заодно разделить фичи по платформам: на Windows только `wav` (декодирование своих WAV для `PlaySoundW`), `playback`/`cpal` — только на Linux. Это убирает `cpal` из Windows-сборки (пункт codex про размер, раздел 7).
- `cargo deny check`, замер размера `focusmute.exe` до и после.

### Этап 6. Выпуск 1.2.0

CHANGELOG со ссылкой на upstream 0.12.0/0.12.1, обновление README (поддержка прошивки 3.x: для Solo — только индикация номеров, Direct выключен до проверки). Каждый этап — отдельный коммит, поэтому откат — `git revert` одного этапа. MSI 1.1.0 сохранить до проверки 1.2.0 на устройстве.

## 7. Разбор ревью codex (документ 23)

Обозначения: ✅ — подтверждено, ◐ — факт верный, но вывод или приоритет завышены, ❌ — надумано или не относится к приложению на одну карту.

### 7.1. Крупные пункты

### 7.3. Что исправить и в каком порядке

Отдельно от переноса upstream, небольшими коммитами:

1. **P1** — ленивое создание и повтор `WasapiMonitor`, повтор в `maintain()`.
2. **P2** — цель переключения из `monitor.is_muted()`. Иконка, звук и OSD без Scarlett. Имя микрофона в подсказке.
3. **P2** — reconnect: сброс флага удаления, `record_failure` при ошибке контекста, `DBT_DEVICEARRIVAL` → немедленная попытка.
4. **P3** — снимать mute при выходе только «свой», откат конфига при ошибке горячей клавиши, обновление пути автозапуска, OSD на активном мониторе, ожидание без карты, строка в README про ASIO/Direct Monitor.

Пункты 1–3 не пересекаются с переносом upstream (другие файлы: `audio.rs`, `shared.rs`, `windows.rs`, `reconnect.rs`). Их можно делать до этапа 0 или параллельно. Пункт 3 с этапом 3 пересекается только в `try_reconnect`, поэтому его лучше влить раньше.
