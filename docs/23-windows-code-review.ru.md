# Код-ревью FocusMute для Windows

22 ноября 2026 года · FocusMute 1.1.0 · ревизия `0705704`

## Главный вывод

В текущей реализации горячая клавиша выполняет `IAudioEndpointVolume::SetMute` для устройства записи Windows по умолчанию (`eCapture/eConsole`). Подключение к Scarlett через драйвер используется для светодиодов, измерителей уровня и кнопки Direct. При подключённом USB-микрофоне или веб-камере Windows может выключить один микрофон, а LED на Scarlett покажет mute, полученный от другого. Флаг Windows сам по себе также не подтверждает, что сигнал заглушён на всех путях. Для WASAPI exclusive результат зависит от аппаратной поддержки mute, которую можно запросить через `QueryHardwareSupport`. ASIO и аппаратный мониторинг требуют отдельной проверки. [Выбор аудиовхода](../crates/focusmute-lib/src/audio.rs#L179), [вызов SetMute](../crates/focusmute-lib/src/audio.rs#L307), [документация Microsoft](https://learn.microsoft.com/en-us/windows/win32/api/endpointvolume/nn-endpointvolume-iaudioendpointvolume).

**Первый приоритет** — привязать команды и индикацию к выбранному входу, исключить непреднамеренное снятие mute и восстановить работу после запуска без карты. Отзывчивость трея стоит улучшать параллельно с надёжностью переподключения. Размер приложения имеет смысл оптимизировать по замерам после этих исправлений.

## Найденные проблемы и исправления

### P1 · Аудиовход и устройство индикации выбираются независимо

Аудиовход Windows всегда берётся из роли Console. Настройка `device_serial` влияет только на открытие Scarlett. Даже там поиск по серийному номеру заканчивается вызовом `open_device()` без найденного пути. Когда нужная карта в списке вторая, код прямо отказывается её открывать. Пункт меню и горячая клавиша способны вызывать mute при наличии монитора Windows, даже если Scarlett отсутствует, а обратная связь при этом подавлена. [Выбор Scarlett при запуске](../crates/focusmute/src/tray/shared.rs#L388), [поиск по серийному номеру](../crates/focusmute-lib/src/device.rs#L1355), [обработка горячей клавиши](../crates/focusmute/src/tray/shared.rs#L791), [обновление трея](../crates/focusmute/src/tray/state/menu.rs#L178).

**Исправление.** Разделить в настройках «Микрофон Windows» и «Устройство индикации». Добавить явный выбор между следованием за входом по умолчанию и закреплением за конкретным capture endpoint. Для Scarlett открывать найденный путь интерфейса, проверять серийный номер открытого устройства и при исчезновении закреплённого входа показывать «Микрофон недоступен». Показывать в трее имя фактического входа и состояние связи с картой. Если требуется mute на самой карте, сначала подтвердить для каждой поддерживаемой модели документированный способ управления и отсутствие сигнала на нужных путях записи. До такой проверки обозначать текущий режим как «Mute микрофона Windows».

### P1 · Выход из утилиты снимает mute, выставленный вне FocusMute

При штатном завершении приложение снимает mute с текущего аудиовхода, если кэш показывает muted. Это касается и микрофона, который был выключен ещё до запуска приложения или был выключен другой программой. PTT хранит только булев флаг и на отпускании использует текущий endpoint. Если устройство сменилось во время удержания, повторное выключение может уйти на другой микрофон. [Завершение работы](../crates/focusmute/src/tray/shared.rs#L886), [обработка PTT](../crates/focusmute/src/tray/shared.rs#L811).

**Исправление.** Сохранять состояние аудиовхода при выходе по умолчанию и отдельно восстанавливать изменённые светодиоды. Для PTT хранить ID и поколение аудиовхода, исходное состояние и факт успешного временного unmute. При смене устройства или настроек PTT завершать для исходного входа, если он доступен и после команды состояние ещё принадлежит этому сеансу PTT. Проверить выход из заранее выключенного микрофона, отказ `SetMute`, смену входа во время удержания и переназначение PTT.

### P1 · Запуск без аудиовхода может требовать перезапуска FocusMute

`WasapiMonitor::new()` открывает default endpoint до регистрации уведомлений. При ошибке монитор в трее остаётся `None` на всё время работы. Повторное подключение USB восстанавливает дескриптор Scarlett, но монитора Windows в этой ветке уже никто не создаёт. У созданного монитора при неудачной смене входа флаг изменения сбрасывается, старый endpoint остаётся активным, а уведомления о добавлении, удалении и смене состояния игнорируются. При автозапуске это особенно заметно, если Focusrite или служба аудио ещё инициализируются. [Создание и обновление монитора](../crates/focusmute-lib/src/audio.rs#L124), [открытие endpoint до подписки](../crates/focusmute-lib/src/audio.rs#L266), [обработка ошибки переключения](../crates/focusmute-lib/src/audio.rs#L324), [запуск потока мониторинга](../crates/focusmute/src/tray/shared.rs#L472).

**Исправление.** Держать подписку MMDevice независимо от наличия активного endpoint. Представить состояния аудио явно — «ожидание», «подключено», «ошибка». При смене цели сразу помечать прежний вход недействительным для новых команд, открывать новый, читать подтверждённый mute и обновлять состояние трея. Если открытие или создание перечислителя временно не удалось, повторять по событию и таймеру с backoff. Если невозможно прочитать `GetMute`, отображать «Состояние неизвестно». События от прежнего endpoint фильтровать по поколению подключения.

### P1 · USB-переподключение ждёт backoff и может затронуть другую карту

Win32-обработчик принимает только `DBT_DEVICEREMOVECOMPLETE` и сводит его к общему флагу, не сверяя путь интерфейса с открытой картой. При отключённом устройстве флаг вообще не считывается, поэтому отложенное удаление может сбросить уже заново открытый дескриптор. Появление устройства не ускоряет следующую попытку, а backoff доходит до 30 секунд. При этом удачное открытие сбрасывает backoff до проверки контекста. Если карта открывается, но контекст не читается, цикл повторяет тяжёлую операцию без предусмотренной задержки. [Уведомления Windows](../crates/focusmute/src/tray/windows.rs#L24), [обработка в трее](../crates/focusmute/src/tray/shared.rs#L528), [сброс backoff при открытии](../crates/focusmute-lib/src/reconnect.rs#L101), [загрузка контекста после открытия](../crates/focusmute/src/tray/state/mod.rs#L257), [события Win32](https://learn.microsoft.com/en-us/windows/win32/devio/wm-devicechange).

**Исправление.** Передавать событие с типом и путём интерфейса. Удаление сопоставлять с текущим путём, а подходящее появление использовать для немедленной попытки подключения после короткого объединения событий. Считать попытку успешной после открытия, проверки карты и загрузки контекста. На временный отказ драйвера, включая отказ в загрузке контекста, назначать следующий срок. События Direct и результаты измерений маркировать поколением устройства, чтобы отложенный результат от прежнего дескриптора не попал в новую сессию. Сохранить резервный таймер на случай пропущенного уведомления.

### P2 · Работа с драйвером задерживает трей и подтверждение mute

Главный цикл синхронно открывает устройство, применяет LED и читает измерители до обработки меню и горячих клавиш. На Windows часть IOCTL уже исполняется в отдельном потоке, однако вызывающая сторона ждёт ответ до пяти секунд на запрос. Настройки вызывают `eframe::run_native` из обработчика меню и приостанавливают обработку логики трея до закрытия окна. Обходной callback переключает системный mute по одной горячей клавише, пока LED, OSD, PTT и переподключение зависят от внешнего цикла. Страница измерителя дополнительно открывает карту и читает её в UI-потоке. [Чтение уровня и порядок обработки событий](../crates/focusmute/src/tray/shared.rs#L687), [ожидание IOCTL](../crates/focusmute-lib/src/device.rs#L553), [вызов настроек](../crates/focusmute/src/tray/state/mod.rs#L430), [измеритель в настройках](../crates/focusmute/src/settings_dialog/ui.rs#L466).

**Исправление.** Сохранить один владеющий дескриптором обработчик команд Scarlett. Передавать ему открытие, обновление LED и чтение уровней асинхронно. Измерителю отдавать последний снимок с признаком актуальности. Объединять запросы на измерение и отбрасывать устаревшие кадры мигания, сохраняя приоритет команд смены состояния. Трей и настройки обновлять по подтверждённому состоянию Windows независимо от результата записи LED. Убрать вложенный цикл настроек из обработчика меню. При быстрых повторных нажатиях сериализовать команды относительно подтверждённого или уже принятого состояния, поскольку инверсия запаздывающего `state.indicator.is_muted()` может дважды отправить одинаковую команду. [Текущий расчёт цели](../crates/focusmute/src/tray/shared.rs#L796).

### P2 · Настройки и автозапуск могут расходиться с рабочим состоянием

Автозапуск записывается только при изменении флажка. Ошибка регистрации уходит в лог, а окно читает состояние из TOML. Это скрывает отказ операции, отсутствующую запись или устаревший путь после переноса portable EXE. Новый hotkey сохраняется до фактической регистрации. При конфликте основной hotkey пытается откатиться на прежнее сочетание, а PTT снимает прежнюю регистрацию и при ошибке оставляет себя выключенным. «Применить» сохраняет файл, но применяет параметры к трею после закрытия окна. [Автозапуск](../crates/focusmute/src/tray/state/mod.rs#L99), [сохранение конфигурации](../crates/focusmute/src/tray/state/mod.rs#L360), [регистрация сочетаний](../crates/focusmute/src/tray/state/mod.rs#L467), [откат сочетаний](../crates/focusmute/src/tray/state/hotkey.rs#L85), [кнопка «Применить»](../crates/focusmute/src/settings_dialog/ui.rs#L441).

**Исправление.** Проверять системные операции в момент применения и видеть рядом с полем их фактический результат. Сохранять только успешно применённое значение и откатывать регистрацию при сбое сохранения. Для автозапуска проверять существование и целевой путь записи, показывать несовпадение с TOML и давать исправить путь из настроек. Проверить MSI и portable, путь с пробелами, переезд EXE, отказ доступа и вход в Windows с подключённой и отключённой Scarlett. При повторном запуске из автозагрузки и вручную сохранять один экземпляр на пользовательский сеанс. Windows вправе отложить запуск приложений из `Run`, поэтому время появления значка после входа измерять отдельно от времени старта процесса. [Документация Microsoft по автозапуску](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys).

## OSD, трей и повседневные настройки

- **OSD на нескольких мониторах.** Текущие позиция и размер используют рабочую область основного экрана и системный DPI. Сохранить ленивое Win32-окно без перехвата фокуса. Добавить выбор «Активный монитор / Основной», вычислять позицию по `GetMonitorInfo`, учитывать DPI целевого окна и реагировать на изменение DPI и топологии. Пересчитывать геометрию при смене позиции, языка или монитора, даже если тип плашки тот же. [Размеры и позиция](../crates/focusmute/src/osd.rs#L61), [рабочая область](../crates/focusmute/src/osd.rs#L203), [показ плашки](../crates/focusmute/src/osd.rs#L292), [рабочая область монитора](https://learn.microsoft.com/en-us/windows/desktop/gdi/multiple-monitor-system-metrics), [Win32 High DPI](https://learn.microsoft.com/en-us/windows/win32/hidpi/high-dpi-reference).
- **Приоритет плашек.** Сейчас каждый положительный отсчёт громкости повторно вооружает таймер OSD, поэтому при длительной речи предупреждение может висеть непрерывно и быстро вытеснять подтверждение mute. Показывать предупреждение по началу эпизода речи с задержкой до повторного показа. Отдельно дать включать подтверждение mute и предупреждение при речи. Для обычного переключения оставлять одно подтверждение по умолчанию, чтобы включённые toast, OSD и звук не дублировали одно действие без выбора пользователя. [Проверка уровня](../crates/focusmute/src/tray/shared.rs#L687), [таймер OSD](../crates/focusmute/src/osd.rs#L326).
- **Статус в трее.** Сделать единый расчёт значка, подсказки и доступности команд по состоянию аудиовхода и Scarlett. Локализовать tooltip и ошибки в одном месте. `tray-icon 0.24.2` уже слушает `TaskbarCreated`, поэтому сначала проверить восстановление значка и состояния после перезапуска Explorer с открытыми и закрытыми настройками. Повторный запуск EXE может открывать настройки существующего экземпляра вместо уведомления о дубликате. [Состояния меню](../crates/focusmute/src/tray/state/menu.rs#L14), [защита от повторного запуска](../crates/focusmute/src/tray/mod.rs#L94).

## Размер и фоновая нагрузка

- **Сначала замерить Windows release.** В уже существующих локальных артефактах `focusmute.exe` — 9 517 056 байт (9,08 МиБ), `focusmute-cli.exe` — 2 779 648 байт (2,65 МиБ). Это ориентир по имеющимся EXE, их соответствие ревизии не подтверждено. В release уже есть LTO, strip и один codegen unit. Сравнивать новые сборки на одном toolchain и target, фиксируя размер обоих EXE и MSI, private working set в трее и время до появления значка. [Профиль release](../Cargo.toml).
- **Начать с точечных изменений зависимостей.** `cargo tree --locked --offline -p focusmute -i cpal` показывает цепочку `cpal ← rodio ← focusmute` на Windows. Windows проигрывает WAV через `PlaySoundW`, но общий код использует `rodio::Decoder`. Проверить разнесение фич `rodio` по платформам, оставив декодирование WAV на Windows и playback на Linux, если текущая версия поддерживает такую сборку. Повторить замеры и проверить пользовательские WAV. Более дорогой эксперимент — нативные настройки Windows вместо `eframe/glow`. Начинать его после оценки выигрыша по EXE, памяти, доступности и поведению при нескольких DPI. [Зависимости](../crates/focusmute/Cargo.toml#L30), [звуковой код](../crates/focusmute/src/sound.rs#L12).
- **Ждать ближайшего срока вместо постоянных пробуждений.** Пока карта отключена, цикл просыпается примерно каждые 50 мс, хотя попытки открытия разнесены на секунды. Фоновый опрос Windows также отправляет снимок каждые 250 мс даже без изменений. Планировать ожидание до ближайшего reconnect, мигания или жеста Direct. Передавать актуальное состояние при смене и использовать редкую проверку как страховку, сохранив подтверждение перехода через 25 мс до появления измерений нового пути. [Опрос аудио](../crates/focusmute/src/tray/shared.rs#L58), [ожидание событий](../crates/focusmute/src/tray/shared.rs#L840).

## Очерёдность и критерии приёмки

| Этап | Что принять |
| --- | --- |
| 1. Целевой микрофон и восстановление | Холодный запуск без Scarlett, затем подключение. Быстрое отключение и подключение, смена USB-порта, сон и пробуждение, перезапуск Windows Audio. Две карты и отдельный USB-микрофон. Mute, PTT и LED относятся к выбранным устройствам. Выход сохраняет уже установленный mute. |
| 2. Развязка трея и драйвера | Искусственно задержать открытие/IOCTL на 5 секунд. Трей, окно настроек и команда mute для доступного входа остаются отзывчивыми. Задержка USB не подменяет подтверждение звукового состояния, старый результат игнорируется. |
| 3. UX Windows | Два монитора с 100% и 150–200% DPI, второй монитор слева, перезапуск Explorer, запись автозапуска с устаревшим путём, конфликт горячей клавиши и запрет записи настроек. Интерфейс показывает применённые значения и объясняет отказ рядом с настройкой. |
| 4. Производительность | Замерять P50/P95 от горячей клавиши до подтверждённого mute, LED и OSD, время от появления интерфейса до готовности и фоновые пробуждения с картой и без неё. Начальные цели для проверки на стенде — P95 до 100 мс для подтверждения mute/OSD в обычном режиме и до 2 с для повторного захвата после готовности интерфейса. Уточнить цели по первой серии измерений. |

## Проверка в рамках ревью

Анализ исходников и локального графа Cargo на Windows. Тесты: `cargo test --locked --offline --workspace` завершилась успешно. Физическое заглушение, ASIO, OSD на нескольких мониторах, реальный вход в систему и USB-переподключение на Scarlett требуют отдельной проверки. Задержки и фоновое потребление ресурсов в этом ревью не измерялись.
